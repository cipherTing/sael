# 网关性能审查与改造

日期：2026-09-25。目标为 **5,000 RPS**，验收网关自身，压测以固定响应替代外部分类服务。模型容量、服务配额和模型推理优化不属于本次范围。

2026-09-27 补充审核缓存与加密凭据验收，随后将分类调用切换为常驻 CLI。旧 SDK 路径结果保留用于对照，不能作为常驻 CLI 的验收结果。

## 行为边界

- 正常请求只保留必要聚合，不保存逐条审核记录、正文或分类分数分布。
- 场景命中、审查失败、输入超限及会话冻结等异常保留记录，文本持久化前去敏。
- 端点、模型、阈值、规则顺序、转发报文与流式行为保持兼容。
- 不增加业务请求并发限制、不新增请求体大小限制。
- Redis 是部署必需组件；PostgreSQL 保留配置与历史数据。

## 已完成的改造

- **正常请求**：不构造审核事件，不做无用的去敏，不保存逐条正文、分数分布或场景明细。只保留计数、比例分母、耗时和 RPM 所需的聚合。首页取消“完成审查”独立卡片及“未匹配放行”占比。
- **异步写入**：请求进入容量 4,096 的内存队列；后台最多等待 2 ms 或收集 128 项后合并，写入 Redis Streams。队列满时背压，不采样丢弃。数据库消费者批量合并后提交，正常退出会排空内存队列。
- **恢复与去重**：Redis 断线时批次刷盘到本地暂存。生产者按序号发布，丢失确认后可重试；数据库统计、异常记录和消费位置在同一事务中提交。数据库只保存一个消费位置，不为正常请求建立逐条去重表。积压只在提交后清理，不按队列长度截断。
- **配置**：PostgreSQL 保存设置，请求读取进程内快照。Redis 通知加速同步，每秒核对数据库，修复漏通知和断线造成的差异。
- **会话冻结**：使用 Redis TTL，迁移尚未过期的旧冻结，保持凭据隔离、到期释放、重试不续期。
- **实时 RPM**：在分类前按秒聚合进网数量，只保留约两分钟 Redis 数据。顶部取最近 60 个完整秒，跟随端点和模型筛选，每 30 秒刷新；不显示峰值。历史曲线按各桶实际时长换算 RPM。
- **请求路径**：复用转发对象、HTTP 连接和 32 KB 缓冲；短文本通过安全的字节上界跳过分词。去敏先筛选必要的模式，保留原有规则及 Unicode 大小写匹配行为。
- **分类接入**：网关复用一个 `sael serve` 子进程，CLI 内部复用纯 Jev API SDK 客户端。审核问题集由 CLI 自己持有，位于 `cli/internal/questions`；SDK 不包含 Sael 的审核业务规则。

## 历史 5,000 RPS 对照（进程内 SDK）

真实 HTTP → 网关 → 固定分类 HTTP 响应 / 转发 HTTP 服务，启用真实 Redis 和 PostgreSQL。负载生成器、网关及两个固定响应服务在同一个本机 Go 进程中；数据库运行于 Docker。下表包含调度等待、HTTP、SDK、入队和响应时间，不包含外部模型推理。负载生成有 256 个工作协程，这不是网关并发上限。

| 流量 | 时长 / 请求数 | 实测 RPS | P50 | P95 | P99 | HTTP 错误 | 逐条记录 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 KB，95% 正常 / 5% 拦截 | 20 s / 100,000 | 4,999.97 | 0.43 ms | 4.74 ms | 71.48 ms | 0 | 5,000 |
| 1 KB，全部拦截 | 30 s / 150,000 | 4,999.94 | 0.45 ms | 5.41 ms | 76.34 ms | 0 | 150,000 |
| 1 KB，SSE 透传 | 10 s / 50,000 | 4,999.91 | 0.46 ms | 4.18 ms | 20.92 ms | 0 | 0 |
| 16 KB，正常审查 | 10 s / 50,000 | 4,999.76 | 4.31 ms | 88.76 ms | 136.07 ms | 0 | 0 |

每组均核对了进网总数、转发数、分类调用数、异常记录数和命中分数样本数。全部入库，无正常请求明细。结束时 Redis 仅保留最后一个已提交批次作为游标边界，待消费积压已清空；全量拦截的瞬时峰值为 239 个批次，结束时压测进程 Go 活跃堆约 29 MB。

最初全量命中只能跑到约 1,841 RPS；分析发现重复去敏与过大的消费批次造成阻塞，修复后才达到目标。没有通过丢记录或跳过真实写入提高吞吐。

### 验收边界

这些是单机、固定响应、10–30 秒的性能结果，不是长时间生产容量承诺。更大历史、持续流式连接、复杂规则、远程存储或集中出现的敏感文本会改变成本。1 MB 历史仍需完整解析，本次未宣称这一大小能达到 5,000 RPS。

内存队列在强制终止进程时有数据丢失窗口；Redis AOF 使用 `everysec`，主机崩溃还可能丢失最近约一秒写入。Redis 与本地磁盘同时不可写时保留批次重试，队列满后会反压请求。备份/恢复须协调 PostgreSQL、Redis 和本地暂存卷。

### 复现

使用独立 PostgreSQL 数据库和两个独立 Redis 实例。测试会清空其中的数据，并修改审核缓存实例的内存上限及淘汰策略。

```sh
cd gateway
export TEST_DATABASE_URL='postgres://user:password@localhost:5432/sael_test?sslmode=disable'
export TEST_REDIS_URL='redis://localhost:6379/15'
export TEST_REVIEW_CACHE_URL='redis://localhost:6380/0'
go test -race ./... -count=1

SAEL_LOAD_TEST=1 SAEL_LOAD_MODE=mixed SAEL_LOAD_RPS=5000 SAEL_LOAD_SECONDS=20 \
  go test ./internal/store -run '^TestGatewayLoad$' -count=1 -v
```

`SAEL_LOAD_MODE` 可选 `disabled`、`clean`、`mixed`（5% 拦截）、`hit`、`sse`；`cache-hit` 与 `cache-mixed` 启用专用审核缓存。`SAEL_LOAD_BODY_BYTES` 设置文本大小。基准与压测应串行运行，避免构建或其他压测抢占 CPU。

集成测试覆盖重复发布/消费、事务中途失败后的回滚与重放、Redis 断线暂存及去敏、配置跨实例同步、冻结迁移和到期、异步入队、正常退出排空，以及 RPM 滚动窗口和筛选。SSE 测试确认首块在上游结束前已经抵达客户端。

总览已在 390 × 844 和 1280 × 720 视口实测：图例随宽度自动换行，曲线按图例实际高度避让；手机显示两行，桌面恢复一行，没有图例横向溢出或文字重叠。RPM 主值为最近一分钟，历史图按时间桶显示 RPM。

## 历史审核复用对照（2026-09-27，进程内 SDK）

Apple M2，Go 1.26.5，真实 PostgreSQL、主 Redis 和独立缓存 Redis。HTTP 请求正文 1,083 字节；经过可信密钥判断、场景缓存、共享 SDK、异步聚合与 PostgreSQL 入库。分类器和转发目的地是本机固定响应服务；没有调用真实 Jev。以下包含负载调度等待。

| 流量 | 请求数 / 时长 | 实测 RPS | P50 | P95 | P99 | 响应错误 | 审核记录 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 重复违规文本，全量拦截 | 100,000 / 20 s | 4,999.64 | 4.11 ms | 25.57 ms | 56.69 ms | 0 | 100,000 |
| 95% 正常送审、5% 重复违规 | 300,000 / 60 s | 4,999.71 | 5.17 ms | 60.11 ms | 145.71 ms | 0 | 15,000 |

- 全量拦截：99,979 次缓存复用，21 次实际分类调用，冷启动并发请求在首次写入前各自完成分类。分类 HTTP 连接累计 6 条。
- 混合流量：14,997 次缓存复用，285,003 次实际分类调用，285,000 次正常转发。正常文本未进入判定缓存，未生成逐条审核记录。
- 进网聚合分别为 100,000 和 300,000，审核记录分别为 100,000 和 15,000，全部入库。缓存记录没有分数或 Jev 耗时样本；分数样本数与真实违规分类调用数一致。
- Redis Streams 瞬时最大长度分别为 105 和 16 个批次，结束时均剩 1 个已提交的游标边界批次，没有待消费积压。
- 混合流量在第 10 秒已建立 65 条分类连接，此后直到第 55 秒没有继续增加。第 15–55 秒 goroutine 为 1,603–1,656，Go 活跃堆为 27–48 MiB，结束时为 34 MiB。这里包含负载生成器、模拟服务与数据库消费者。

排查并修复了请求级缓存超时影响其他请求的问题：单次取消或超时原本会关闭实例内的缓存读取，等待下一次配置同步。现在只让该次请求回退到正常送审；取消读写后其他请求仍能立即复用，已有竞态回归测试。

当时 SDK 单独微基准（1,000 次、并行）为 76.6 μs / 次、92.6 KB / 次、485 次分配，包含本机 HTTP 和 JSON 编解码。这组结果测的是旧调用路径。

另以共享 SDK 连续执行 440,620 次调用（约 39 秒），外部 `lsof` 每 5 秒采样：文件描述符始终为 21，常驻内存为 25.3–27.3 MiB，没有持续增长。此观测不依赖网关负载测试中 macOS 不支持的 `/proc` 文件描述符枚举。

这些结果验证单机模拟负载下的吞吐和数据完整性。它们不代表远程数据库、真实模型响应或长时间生产流量的容量；60 秒资源采样也不能替代数小时的持续观察。原始负载日志、资源采样和页面截图保存在本机 `~/tmp/sael-implementation-20260927/`。

## 常驻 CLI 验收（2026-09-27）

当前链路为：HTTP 客户端 → 网关 → 缓存 / 同一个 `sael serve` 进程 → 模拟 Jev。网关只通过私有本机 HTTP 连接与 CLI 通信；SDK 客户端及 Jev 连接池位于 CLI 内部。每次压测从缓存未预热状态开始，正文 1,083 字节。

| 流量 | 请求数 / 时长 | 实测 RPS | P50 | P95 | P99 | 响应错误 | 审核记录 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 重复违规文本，全量拦截 | 100,000 / 20 s | 4,998.61 | 4.52 ms | 27.35 ms | 73.98 ms | 0 | 100,000 |
| 95% 正常送审、5% 重复违规 | 300,000 / 60 s | 4,980.18 | 33.16 ms | 447.05 ms | 584.68 ms | 0 | 15,000 |

- 全量拦截实际调用 CLI/Jev 228 次，其余 99,772 次复用缓存。首次判定完成前到达的并发请求分别送审，没有把它们记成缓存命中。
- 混合流量实际调用 CLI/Jev 285,006 次，缓存复用 14,994 次，转发 285,000 次。计数与记录全部入库，正常请求没有逐条明细，缓存没有伪造分数样本。
- 两组 Redis 待消费积压均清空，最终保留 1 个已提交游标边界批次。混合流量在第 30 秒达到 224 条 Jev 连接，第 55 秒仍为 224。
- CLI 单独并行微基准连续执行 341,144 次调用，平均 108.2 μs / 次。正式测量阶段始终为同一个 CLI PID；每 5 秒观察到文件描述符恒定为 23，常驻内存约 22.5–23.7 MiB。网关侧分配为 23.4 KB / 次，不包含 CLI 进程内的分配。

这些是同一开发机上的模拟服务结果。常驻 CLI 增加了进程间通信和编解码成本，本次混合负载的 P95/P99 高于上述 SDK 对照；没有把旧数据沿用为 CLI 的性能结论。压力调度目标为 5,000 RPS，混合流量完成尾部请求后实测约 4,980 RPS。

生命周期与错误路径另有自动化测试：连续调用复用、并发配置隔离、取消到达 Jev、取消不终止共享 CLI、响应读取超时类别、父进程管道 EOF 清理、CLI 被杀后的错误上报与网关退出。CLI 未就绪时不开放网关监听，CLI 异常后不改走 SDK。单次 `sael check` 的原有测试继续通过。

原始日志位于本机 `~/tmp/sael-cli-implementation-20260927/`。复现时使用上面的测试环境与 `SAEL_LOAD_MODE=cache-hit` / `cache-mixed`；测试会自行编译、启动并关闭真实 CLI 可执行文件。

## 资料依据

- [Go net/http](https://pkg.go.dev/net/http)：Client / Transport 应复用，连接池与业务并发上限含义不同。
- [Go ReverseProxy](https://pkg.go.dev/net/http/httputil#ReverseProxy)：缓冲池及流式 flush 行为。
- [Redis Streams](https://redis.io/docs/latest/develop/data-types/streams/)：持久消息流和消费进度。
- [Redis Pub/Sub](https://redis.io/docs/latest/develop/pubsub/)：通知会丢失，不能充当可靠日志或唯一配置同步机制。
- [Redis 持久化](https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/)：AOF 的刷盘配置决定故障丢失窗口。
- [pgx BatchResults](https://github.com/jackc/pgx/blob/master/batch.go)：批量减少往返，需要检查 Close 返回的错误。

资料通过官方文档、Context7 与本地依赖源码交叉检查。普通 pipeline 只减少往返，不意味着多条命令原子执行。
